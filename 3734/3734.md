# LeetCode 3734 – Lexicographically Palindromic Permutation

## 📌 Problem

Given two strings `s` and `target`, rearrange the characters of `s` to form a **palindrome** that is **lexicographically greater than `target`**.

Among all valid palindromic permutations, return the **lexicographically smallest** one.

If no such palindrome exists, return an empty string.

---

## 💡 Approach

A palindrome has a special structure:

* The first half determines the second half.
* If the length is odd, exactly one character is placed in the middle.
* The characters in the second half are the reverse of the first half.

So instead of generating all permutations, we only need to construct the **first half**.

### Step 1: Count Characters

Count the frequency of every character in `s`.

For a palindrome:

* At most one character can have an odd frequency.
* If more than one character has an odd frequency, a palindrome cannot be formed.

---

### Step 2: Build the First Half

For every character:

```text
halfCount[c] = frequency[c] / 2
```

These characters are enough to construct the first half of the palindrome.

The remaining character, if any, becomes the middle character.

---

### Step 3: Find the Smallest Palindrome Greater Than `target`

We try to construct the first half as small as possible while making the complete palindrome greater than `target`.

We compare the palindrome with `target` from left to right.

At every position:

1. Try to place the smallest available character.
2. If choosing that character can make the final palindrome greater than `target`, use it.
3. Otherwise, continue trying larger characters.
4. Once a position is made strictly greater, fill all remaining positions with the smallest possible characters.

This greedy strategy gives the **lexicographically smallest valid palindrome**.

---

## 🔍 Key Observation

For a palindrome:

```text
Palindrome = Left + Middle + reverse(Left)
```

Therefore, comparing palindromes is mainly determined by their left halves.

For example:

```text
Left = "abc"
Middle = "d"

Palindrome = "abc" + "d" + "cba"
           = "abcdcba"
```

So we can focus on finding the smallest valid `Left` that produces a palindrome greater than `target`.

---

## 🧠 Algorithm

1. Count the frequency of each character in `s`.
2. Check whether a palindrome can be formed.
3. Construct the frequency array for the left half.
4. Extract the middle character if the length is odd.
5. Start constructing the answer from left to right.
6. At each position:

   * Try available characters in increasing order.
   * Construct the corresponding palindrome.
   * Check whether it is lexicographically greater than `target`.
7. Once a valid greater prefix is found, fill the remaining positions using the smallest available characters.
8. Mirror the left half around the middle.
9. Return the resulting palindrome.
10. If no valid palindrome exists, return `""`.

---

## 💻 C++ Solution

```cpp
class Solution {
public:
    string lexPalindromicPermutation(string s, string target) {
        int n = s.size();
        int half = n / 2;

        vector<int> cnt(26, 0);

        // Count characters
        for (char c : s) {
            cnt[c - 'a']++;
        }

        // Check whether a palindrome can be formed
        int odd = 0;
        char mid = 0;

        for (int i = 0; i < 26; i++) {
            if (cnt[i] % 2) {
                odd++;
                mid = char('a' + i);
            }
        }

        if (odd > 1) {
            return "";
        }

        // Count characters available for the first half
        vector<int> halfCnt(26);

        for (int i = 0; i < 26; i++) {
            halfCnt[i] = cnt[i] / 2;
        }

        // Function to build palindrome from left half
        auto build = [&](const string& left) {
            string res = left;

            if (n % 2) {
                res += mid;
            }

            string rev = left;
            reverse(rev.begin(), rev.end());

            res += rev;

            return res;
        };

        // Greedily construct the smallest left half
        string left;

        for (int pos = 0; pos < half; pos++) {

            for (int c = 0; c < 26; c++) {

                if (halfCnt[c] == 0)
                    continue;

                left.push_back(char('a' + c));
                halfCnt[c]--;

                // Build remaining smallest possible suffix
                string temp = left;

                vector<int> remaining = halfCnt;

                for (int x = 0; x < 26; x++) {
                    while (remaining[x] > 0) {
                        temp.push_back(char('a' + x));
                        remaining[x]--;
                    }
                }

                string candidate = build(temp);

                if (candidate > target) {
                    // We have found a valid prefix.
                    // Complete the answer with the smallest characters.

                    string finalLeft = left;

                    for (int x = 0; x < 26; x++) {
                        while (halfCnt[x] > 0) {
                            finalLeft.push_back(char('a' + x));
                            halfCnt[x]--;
                        }
                    }

                    string ans = build(finalLeft);

                    if (ans > target)
                        return ans;
                }

                // Undo the choice
                halfCnt[c]++;
                left.pop_back();
            }

            // If no character works at this position
            // no valid palindrome can be constructed.
            return "";
        }

        // Special case when half == 0
        string ans = build(left);

        if (ans > target)
            return ans;

        return "";
    }
};
```

---

## ⚠️ Important Cases

### Case 1: More than one odd frequency

Example:

```text
s = "abc"
```

Frequencies:

```text
a -> 1
b -> 1
c -> 1
```

There are 3 odd frequencies, so a palindrome cannot be formed.

Return:

```text
""
```

---

### Case 2: Already the smallest possible palindrome

If the smallest palindromic permutation is already greater than `target`, return it directly.

---

### Case 3: No palindrome is greater than `target`

If even the largest possible palindromic permutation is not greater than `target`, return:

```text
""
```

---

## ⏱️ Complexity

Let `n = s.length()`.

### Time Complexity

```text
O(26 × n)
```

Since there are only 26 lowercase English characters, this is effectively:

```text
O(n)
```

### Space Complexity

```text
O(n)
```

for constructing the palindrome and temporary strings.

---

## ✅ Why This Works

The palindrome is completely determined by its first half and the middle character.

Therefore:

```text
Minimize first half
        ↓
Minimize complete palindrome
```

We construct the first half from left to right and always try characters in increasing order.

Once a choice makes the resulting palindrome strictly greater than `target`, the remaining characters should be placed in sorted order to obtain the smallest possible answer.

Thus, the greedy construction produces the **lexicographically smallest palindromic permutation greater than `target`**.
